# /pr-watch — 業界ウォッチ&ネタ提案スキル

RSSで競合・業界の新着を収集し、トレンドレポートとリリース案を `press/reports/` に保存する。

## 規約上の注意(厳守)

- 収集・保存するのは**見出し・リンク・日付のみ**。他社リリースの本文を複製・転載しない
- レポートで他社リリースに言及するときは見出し+リンク引用にとどめる
- watch.mjs は手動実行のみ。cron等での高頻度ポーリングを設定しない

## フロー

### 1. 収集スクリプト実行

```bash
cd press && node scripts/watch.mjs
```

- **exit 0**: `press/data/inbox/YYYY-MM-DD.json` に新着が保存される
- **exit 1(全フィード失敗)**: ネットワーク問題。直近の `press/data/inbox/*.json` があればそれで分析を続行し、レポートに「本日分は取得失敗、◯月◯日分で分析」と明記。動作確認だけなら `--sample` を案内
- **「有効なフィードがありません」**: `press/config/watchlist.json` が未設定。ユーザーに競合企業のPR TIMESページURL(`prtimes.jp/main/html/searchrlp/company_id/XXXXX`)を聞き、company_idを登録してから再実行

### 2. 人気リリースの補完取得(ベストエフォート)

新着RSSにはランキング情報がないため、可能なら WebFetch で PR TIMES のランキングページ
(`https://prtimes.jp/main/action.php?run=html&page=ranking` または `https://prtimes.jp/ranking/`)から
**上位リリースの見出しのみ**を取得する。失敗したらスキップし、レポートに「ランキング取得不可、新着分析のみ」と明記(エラーで止めない)。

### 3. 分析

本日のinbox JSON(+必要なら直近数日分)を読み、以下を分析する:

- **競合動向**: どの会社が・どんなテーマで・どのくらいの頻度で出しているか
- **業界トレンド**: Google Newsの見出しから今週の話題を抽出(デジライズが時事コメントや調査で乗れるものはどれか)
- **伸びるタイトルのパターン**: 新着・人気リリースの見出しから、数字の使い方・キーワード・型を抽出

### 4. レポート保存

`press/reports/YYYY-MM-DD-watch-report.md` に保存:

```markdown
# ウォッチレポート YYYY-MM-DD

## 今週のトレンドサマリ(3〜5行)
## 競合動向(会社別に見出し+リンク)
## 刺さるタイトルのパターン分析
## リリース案(3〜5件)
```

リリース案は各件に必ず含める:
**仮タイトル**(数字入り・30〜40字) / **切り口**(なぜ今か) / **使用テンプレート**(new-service等) /
**推奨配信時期**(火〜木10〜11時台で具体日) / **狙うキーワード** / **参考リンク**

### 5. 締め

レポートの要点とリリース案を提示し、
「この案で書く場合は `/press-release` を実行してください(案の番号を伝えてもらえれば引き継ぎます)」と案内する。
