# 導入事例 運用ガイド

法人リスキリング導入企業の最終報告資料から、見込み客向けの導入事例を作成・公開するためのワークフロー。

## 仕組み(自動生成)

最終報告MTG資料のPDFをアップロードして `/case-study` スキルを呼ぶと、以下が自動生成される:

- **導入事例の原稿ファイル**: `case-studies/<企業スラッグ>/draft.md`
  - `TEMPLATE.md` の構成に準拠
  - `【画像挿入位置①:企業ロゴ】`(タイトル直前)と `【画像挿入位置②:社内または社員の写真】`(リード文直後)のマーカー入り。承諾後に先方から支給されたロゴ・写真をこの位置に挿入するだけで完成
- **掲載許可依頼文**: `case-studies/<企業スラッグ>/approval-request.md`(ロゴ・写真の支給依頼込み)

## 公開先(Webページ化する場合)

事例ページは `ai-adoption-survey/public/cases/` 配下の静的HTML。
mainにマージすると Vercel が自動デプロイし、以下のURLで公開される。

- 事例一覧: `https://shindan.digirise.ai/cases/`
- 株式会社トップ様: `https://shindan.digirise.ai/cases/top/`

HTMLは1ファイル完結(CSSインライン・外部依存はGoogle Fontsのみ)なので、
将来 digirise.ai 本体へ移す場合もファイルをそのまま持っていけばよい。

## 事例作成 → 公開のワークフロー

1. **素材受領**: 最終報告MTGの納品資料(PDF)を受け取り、アップロードして `/case-study` を実行
2. **原稿生成(自動)**: PDFから定量データを抽出し、原稿ファイル `draft.md` を生成
   - 掲載する: 導入前後のKPI比較・推移データ・定着状況・活用業務の拡大・ROI試算・匿名化した受講者の声・プログラム概要
   - 掲載しない: 動画視聴状況、**受講者の個人名**(声はすべて匿名化する)、社外秘情報
3. **顧客へ掲載許可を依頼**: `<企業スラッグ>/approval-request.md` の依頼メールを送付
   - 原稿(またはプレビューURL・スクリーンショット)を添える
   - 掲載承諾と同時に **ロゴデータと写真** の提供を依頼する
4. **承諾後、ロゴ・写真を挿入するだけで完成**:
   - 受領素材は `case-studies/<企業スラッグ>/assets/` に保存し、原稿の `【画像挿入位置①/②】` に対応
   - Webページ化する場合: ロゴ → `ai-adoption-survey/public/cases/<企業スラッグ>/client-logo.png`、写真 → 同 `client-photo.jpg`(ファイルを置くだけで自動表示。無い間はスロット非表示でレイアウトは崩れない)
5. **公開**: 原稿の `status` を `published` に更新。Webページはmainへマージ → 自動デプロイ。`cases/index.html` の一覧にカードを追加する

## 掲載前チェックリスト

- [ ] 個人名が一切載っていない(受講者の声は匿名化済みか)
- [ ] 数値がすべて最終報告資料と一致している
- [ ] ROI試算の前提(時給換算・期間・助成金)の注記がある
- [ ] 「成果を保証するものではありません」の注記がある
- [ ] 顧客の書面(メール可)による掲載承諾を得ている
- [ ] 企業名・ロゴ・写真の使用許可を得ている
