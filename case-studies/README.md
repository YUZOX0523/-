# 導入事例 運用ガイド

法人リスキリング導入企業の最終報告資料から、見込み客向けの導入事例**原稿**を作成するためのワークフロー。
**公開先はWordPressで管理している自社サイト**。掲載は完成した原稿と素材を使って**社内担当が手動で行う**。このリポジトリからの自動デプロイはしない。

## 仕組み(自動生成)

最終報告MTG資料のPDFをアップロードして `/case-study` スキルを呼ぶと、以下が自動生成される:

- **チェック用原稿(Markdown)**: `case-studies/<企業スラッグ>/draft.md`
  - `TEMPLATE.md` の構成に準拠。導入企業へのチェック依頼に使う
  - `【画像挿入位置①:企業ロゴ】`(タイトル直前)と `【画像挿入位置②:社内または社員の写真】`(リード文直後)のマーカー入り
- **WordPress入稿用**: `case-studies/<企業スラッグ>/wordpress.html`
  - Gutenbergブロックマークアップ。WordPressのコードエディターに全文コピペするだけで記事になる
  - 冒頭コメントに貼り付け手順とタイトル欄用のタイトルを記載
- **掲載許可依頼文**: `case-studies/<企業スラッグ>/approval-request.md`(ロゴ・宣材写真の支給依頼込み)

## 事例作成 → 公開のワークフロー

1. **素材受領**: 最終報告MTGの納品資料(PDF)を受け取り、アップロードして `/case-study` を実行
2. **原稿生成(自動)**: PDFから定量データを抽出し、原稿ファイル `draft.md` を生成
   - 掲載する: 導入前後のKPI比較・推移データ・定着状況・活用業務の拡大・ROI試算・匿名化した受講者の声・プログラム概要
   - 掲載しない: 動画視聴状況、**受講者の個人名**(声はすべて匿名化する)、社外秘情報
3. **導入企業へ原稿チェック+掲載許可を依頼**: `<企業スラッグ>/approval-request.md` の依頼メールを送付
   - 原稿 `draft.md`(またはプレビューURL)を添える
   - 掲載承諾と同時に **ロゴデータと宣材写真** の提供を依頼する
   - 修正依頼があれば `draft.md` と `wordpress.html` の両方に反映する
4. **承諾後**: 受領したロゴ・宣材写真を `case-studies/<企業スラッグ>/assets/` に保存し、
   原稿の frontmatter を `status: approved` に更新して `approved_date` を記入
5. **WordPressで公開(社内担当が手動)**:
   1. WordPressで新規投稿 → 右上「…」→「コードエディター」→ `wordpress.html` の中身を全文貼り付け
   2. タイトル欄に冒頭コメント記載のタイトルを入力、アイキャッチ画像に宣材写真を設定
   3. 記事内の【画像挿入位置①/②】の指示段落を、アップロードしたロゴ・宣材写真の画像ブロックに差し替えて公開
   4. 掲載できたら frontmatter を `status: published` に更新する

※ Vercelの事例サイト(`case-studies/site/`・case-studiesプロジェクト)は、WordPress掲載前の
   社内確認・顧客チェック用プレビューとして任意で使う(正式な公開先はWordPress)。

## 掲載前チェックリスト

- [ ] 個人名が一切載っていない(受講者の声は匿名化済みか)
- [ ] 数値がすべて最終報告資料と一致している
- [ ] ROI試算の前提(時給換算・期間・助成金)の注記がある
- [ ] 「成果を保証するものではありません」の注記がある
- [ ] 顧客の書面(メール可)による掲載承諾を得ている
- [ ] 企業名・ロゴ・写真の使用許可を得ている
