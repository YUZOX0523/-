# 提案前フックサイト（proposal-site）

デジライズの **「法人リスキリング」**（法人リスキリング365 ＋ AI人材養成講座）を
提案する**前**に見せる、1ページのアーティファクト。
「AI活用後の自社の姿」がイメージでき、費用対効果が期待できそうだと感じてもらい、
その場で質疑ができる状態をつくるための道具。

契約を取る資料ではない。**提案本番へ進む合意を取るための掴み**。

---

## 何を伝える道具か

**「全社員が使い、リーダーが変える」= 2層同時推進。**
2つのサービスを**同時にスタートして並行で走らせる**（順番ではない）。

| | Layer 1｜全社基盤 | Layer 2｜推進中核 |
|---|---|---|
| サービス | **法人リスキリング365**（全社員） | **AI人材養成講座**（推進層・6か月） |
| 到達レベル | Lv.1 使う ／ **Lv.2 チャットボットを作れる** | **Lv.3 AIエージェントを設計できる** |
| 例えると | チョコザップ（いつでも通える） | ライザップ（パーソナルトレーナー付き） |

この**到達レベルの差**が2つのサービスの違いそのもので、デモで実演する唯一の論点。

100名なら70名が日常利用層／30名が推進・成果創出層。段階ではなく**役割分担**。
365は全社員に配るのが原則（使う人だけに配ると社内に断層ができ、成果が横に広がらない）。

---

## 使い方（営業）

Claude Code に投げるだけ。目標10分。

```
/proposal-site https://提案先のURL
```

ツールを指定する場合：

```
/proposal-site https://提案先のURL CopilotとClaude Codeで
```

分かっている情報があれば足すと精度が上がる（なくても動く）：

```
/proposal-site https://提案先のURL
従業員400名くらい、商談相手は製造部長、人手不足の話をされている
```

出てくるもの：アーティファクトのURL 1本。ブラウザで開いて商談で使う。

---

## 商談での使い方

| 章 | やること | 時間 |
|---|---|---|
| 01 前提の確認 | 「この理解で合っていますか」と聞く。**ズレの指摘が一番の収穫**なのでメモする | 2分 |
| 02 到達レベルと業務変化 | 相手の部門と職位を選んで開く。相手自身の仕事が出るので反応が変わる。<br>カードに「どちらのサービスで到達するか」が出る | 5分 |
| 03 再現デモ | 各層**1本ずつ**。02のカードの「デモを見る」から飛ぶと文脈がつながる。<br>**承認待ちキューのボタンは相手に押してもらう**（半自動化が一番伝わる） | 4分 |
| 04 効果の見立て | 時間単価スライダーを**相手の実額に一緒に動かしてもらう**。これが効く | 3分 |
| 05 想定Q&A | 質問が出たら該当項目を開く。出なければ飛ばす | — |
| 06 次のステップ | 「次回、提案資料で投資額とスケジュールをご説明します」で締める | 1分 |

- 社名は入っていないので、URLをそのまま相手に送っても情報が漏れない。
- 投資額は載っていない。金額の話は提案資料の役割として残してある
  （公的支援2制度の存在だけ触れてある）。
- 印刷・PDF化すると章構成のまま出る（デモは動かないので、その場で見せることが前提）。

## 中身

```
proposal-site/
├── templates/proposal-site.html   アーティファクト本体（CONFIG 1箇所を差し替えて使う）
├── knowledge/
│   ├── service-philosophy.md      ★最初に読む。サービスの思想と2層同時推進
│   ├── role-tasks.md              職種・職位別 到達レベルと業務変化カタログ
│   ├── tools.md                   ツールの選び方と、自動化が伝わるデモ台本の型
│   ├── design-brand.md            ロゴ規定・コーポレートカラーの適用・誠実さの装置
│   └── roi-and-qa.md              試算ルールと想定質疑ライブラリ
├── scripts/brand-color.mjs        提案先HPからコーポレートカラーを抽出＋コントラスト検算
└── assets/digirise-logo.png       ロゴ（テンプレートにData URIで埋め込み済み）
```

スキル定義は `.claude/skills/proposal-site/SKILL.md`。

`templates/proposal-site.html` は**そのまま開ける完成見本**（精密部品製造・従業員約320名の
架空企業／4ツール全選択）になっている。まず開いて動かしてみると、何が作られるか分かる。

### デモで見せるもの

**普通のチャット処理は入れていない。**「もう知っている」と流されて逆効果になるため。

| 層 | 実演内容 | 画面の流れ |
|---|---|---|
| **365**（全社員） | 業務専用チャットボットを**作って同僚に配る** | 設定フォーム（入力はこれだけ）→ 同僚が使っている会話 → 配布後4週間の利用実績 |
| **養成講座**（推進層） | 業務プロセスを**エージェントに設計する** | 人の工程 8→1〜2 の比較 → 動作設計（人の判断を明示）→ **稼働ログ（誰も操作していない）** → **承認待ちキュー（ボタンが押せる）** → 30日の稼働実績 |

## 対応ツール

`CONFIG.tools` で複数選択する。**選んだものだけ**が画面に出て、業務カードもデモも自動で絞られる。

| ID | 表記 | Layer 1（ボット作成） | Layer 2（エージェント設計） |
|---|---|---|---|
| `gemini` | Gemini（Google Workspace） | カスタムAIを作る | Apps Script と組み合わせて自動化 |
| `copilot` | Copilot（Microsoft 365） | エージェント（ボット）を作る | Copilot Studio ＋ Teams 承認 |
| `claudecode` | Claude Code | — | データ分析・監視・既存資産の解読 |
| `codex` | Codex | — | システム連携・業務処理の実装 |

既定は `["gemini","copilot"]`（これだけで両層が成立する）。推奨は3つまで。
`claudecode` / `codex` を足すのは情報システム部門が明確にある企業のみ。

## 手で直したいとき

`CONFIG` の値だけ書き換える。CSS・HTML・描画スクリプトは触らない。
差し替え箇所はファイル冒頭のコメントに列挙してある。

編集後の構文チェック：

```bash
node -e 'const s=require("fs").readFileSync("proposal-site/templates/proposal-site.html","utf8");
const m=s.match(/<script>([\s\S]*)<\/script>/);new Function(m[1]);console.log("OK")'
```

コーポレートカラーの抽出だけ単体で試す：

```bash
node proposal-site/scripts/brand-color.mjs https://提案先のURL
```

外部取得ができない環境では、HTMLを保存して渡す：

```bash
curl -sL https://提案先のURL > /tmp/p.html
node proposal-site/scripts/brand-color.mjs --stdin https://提案先のURL < /tmp/p.html
```

## 守っていること

- **社名を書かない** — 呼称は「貴社」。URLを共有しても提案先が特定されない
- **2層は同時に立ち上げる** — 「まず基盤を作ってから育成」「まず少数から」は書かない
- **365は全社員に配る** — 使う人だけに配ると社内に断層ができ、成果が横に広がらない
- **前提を開示する** — 公開情報のみで作った想定であること、成果を保証しないことを明記
- **画面は再現イメージと明示する** — 各社の実画面ではないことを画面上に表示
- **投資額を載せない** — 提案資料の役割を奪わない
- **AIが判断する話にしない** — 業務カードは「人が何に時間を使えるようになるか」で締める
- **全自動の絵にしない** — エージェントには人が判断する工程を必ず残す
- **人員削減を示唆しない** — 削減時間は振り替え先があるものとして扱う
