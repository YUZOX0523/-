# デザイン・ブランド規定

このテンプレートのデザインは「誠実な印象」を目的に設計されている。
**CSS と HTML は触らない。** 触らなくても、色1色と文言だけで提案先ごとに変わるようになっている。

---

## 1. デジライズのロゴ

- ロゴは `proposal-site/assets/digirise-logo.png` の1点のみを使う。
  テンプレートには Data URI として埋め込まれており、**アーティファクトは外部通信なしで表示できる**
  （アーティファクトは外部ホストへの通信が禁止されているため、画像URLの参照は表示されない）。
- 表示位置はヘッダー左上に固定。白い角丸プレートの上に置く。
  暗いテーマでもロゴの文字色（ほぼ黒）が沈まないための処置なので、**プレートを外さない**。
- ロゴの変形・色替え・上下の文字追加は不可。高さは 22px（ヘッダー内）。
- ロゴの右には「提案前のご確認用」の役割表示のみを置く。提案先の社名は入れない。
- フッターにはブランド4色（シアン／バイオレット／ブルー／オレンジ）のドットのみを置く。
  この4色を**ページの他の場所で使わない**。ページの主役は提案先の色である。

```
--dr-cyan:#22E3F5   --dr-violet:#6A11F0   --dr-blue:#1B8CFF   --dr-orange:#FF3D0D
```

## 2. 提案先のコーポレートカラー

`CONFIG.brand.color` に**1色だけ**入れる。ページ全体の色（見出し・アクセント・グラフ・
ヒーローの背景・ボタン）はここから自動で導出される。

```js
brand: { color: "#0F5C8C", source: "コーポレートサイトのヘッダー・見出し色より" }
```

### 抽出手順

```bash
node proposal-site/scripts/brand-color.mjs https://提案先のURL
```

`meta theme-color` → CSS カスタムプロパティ → インラインCSS → 外部CSS の順に重みづけして
候補を出し、明／暗テーマでのコントラスト比まで検算する。**出力の推奨値をそのまま使ってよいが、
必ずサイトを目で見て確認する**（ロゴの色とサイトのブランド色は一致しないことが多い）。

社内ネットワークやプロキシで外部取得ができない環境では、HTMLを保存して渡す：

```bash
curl -sL https://提案先のURL > /tmp/p.html
node proposal-site/scripts/brand-color.mjs --stdin https://提案先のURL < /tmp/p.html
```

### 色の選び方

| 状況 | 選ぶ色 |
|---|---|
| 明確なブランド色が1色ある | それ |
| 2色使い（例：紺＋赤） | **面積の広いほう**。狭いほうは使わない |
| 色数が多い・パステル中心 | 見出しやナビに使われている最も濃い色 |
| 抽出できない | ロゴの主色。それも曖昧なら濃紺 `#1F3A5F`（無難で誠実に見える） |

### やってはいけないこと

- **蛍光色・原色に近い彩度の高い色をそのまま入れない。** 画面全体が安っぽくなる。
  同系色で彩度を落とした色に置き換える。
- 黒（`#000000`）・白・グレーを入れない。導出される色が全部グレーになり、
  デザインが崩れる。ブランドがモノトーンの会社は濃紺 `#1F3A5F` を使う。
- スクリプトが「△ 要調整」と出したら**必ず直す**。文字が読めない画面を提案先に見せることになる。
  彩度を保ったまま明度を下げた同系色に差し替える。

### 色の使われ方（自動）

| 用途 | 導出 |
|---|---|
| 見出し・強調文字・数値 | 明: 指定色を78%黒側へ寄せた濃色 / 暗: 白側へ寄せた明色 |
| ボタン・選択中のチップ | 濃色（白文字が乗る） |
| ヒーロー背景・注記の地色 | 指定色を7〜14%だけ乗せた極薄の面 |
| グラフのバー・箇条書きの点 | 指定色そのまま |

## 3. 誠実な印象をつくっている要素（外さない）

この4つを消すと、資料の性格が「営業パンフレット」に変わる。

1. **ヒーロー直下の前提開示帯**（`CONFIG.company.notice`）
   公開情報のみで作った想定であること、社名を記載していないこと、成果を保証しないことを明示する。
2. **デモの「画面はすべて再現イメージです」バッジ**と各画面下の注記。
3. **04 の「この試算の前提」ブロック**（`CONFIG.roi.assumptions`）と投資額を出していない旨の注記。
4. **06 の締めの文**（`CONFIG.next.stance`）。明朝体で組まれた唯一の箇所で、
   「AIを入れること自体が目的ではない」という姿勢を書く。

**社名は入れない。** 提案先の呼称は「貴社」で通す。プロフィールのチップは
業種・規模・拠点数・対象人数など、**社名が特定されない属性のみ**にする。
これにより、URLを共有しても提案先の情報が漏れない。

## 4. デザインの構造（把握しておくと説明しやすい）

- **色**：提案先の色1色から全体を導出。ニュートラルはアクセント側へわずかに寒色に振った
  `#13151B`（文字）／`#FAFAFB`（地）／`#E3E5EC`（罫）。緑・黄・赤は状態表示専用でアクセントとは別枠。
- **書体**：3役。見出しはゴシック太字（字間 -0.03em）、本文はゴシック（行間1.85／日本語に必要な余白）、
  数値とラベルは等幅（`tabular-nums` で桁を揃える）。締めの1文のみ明朝。
  ウェブフォントは使っていない（アーティファクトは外部通信ができないため、
  読み込み失敗で書体が崩れる事故を避ける設計）。
- **レイアウト**：左に「本日の進行」レール（01〜06）。商談中に「では3番のデモを」と
  口頭で誘導できるよう、章番号が会議の進行順そのものになっている。
- **明暗テーマ**：閲覧者の環境に追従する。3状態（明示的な明／暗、OS任せ）すべてで検証済み。
- **印刷**：ヘッダーとレールが落ち、各セクションが分割されないように組んである。
  PDF化して置いていくこともできる（ただしデモは動かないので、その場で見せることが前提）。

---

## 5. 変更していい範囲

| 対象 | 可否 |
|---|---|
| `CONFIG` の値（文言・色・カード・デモ・数値） | ◯ 自由 |
| `<title>`（提案先ごとの固有名。社名は入れない） | ◯ 必ず変える |
| `CONFIG.company.notice` / `footMeta` / `roi.assumptions` の削除 | ✕ |
| CSS・HTML構造・描画スクリプト | ✕ |
| セクションの追加・削除 | ✕（必要な内容は既存セクション内に収める） |
