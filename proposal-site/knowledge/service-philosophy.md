# 提案するサービスの思想（必読）

このフックツールが売るのは **「法人リスキリング」パッケージ** であり、AI活用全般ではない。
何を書いてよく、何を書いてはいけないかは、すべてこの思想から決まる。

出典：デジライズ提案資料『法人リスキリング365／AI人材養成講座』

---

## 1. パッケージの構成

| | Layer 1｜全社基盤 | Layer 2｜推進中核 |
|---|---|---|
| サービス | **法人リスキリング365**（ストック） | **AI人材養成講座**（研修） |
| 対象 | **全社員** | 推進・成果創出を担う層 |
| 役割 | 全社員のAIリテラシーと業務活用力を底上げ | 業務テーマを実装し、成果を出すリーダーを育成 |
| 中身 | 動画400本以上（継続更新）／レベル別ワークショップ参加し放題／オンラインサロン＋チャット相談／自社開発LMS（学習・進捗・理解度の可視化） | 6か月／動画10h／ワークショップ4回／業務テーマの実装伴走 |
| 例えると | チョコザップ（いつでも通える） | ライザップ（パーソナルトレーナー付き） |

**キャッチコピー：「全社員が使い、リーダーが変える。」**
サブ：生成AIの全社定着と推進人材育成を同時に実現

### 2層は「同時スタート・同時並行」で垂直に立ち上げる

**最重要。順番ではない。** 365を先に入れて様子を見てから養成講座、という段階論ではなく、
**2つのサービスを同時に開始し、並行して走らせる**。提案資料の言葉では
「全社基盤と推進人材を、2つのサービスで**同時に立ち上げる**」。

```
       ┌──────────────────────────────────┐
同時に │ 全社基盤（365）      … 全社員が学び、使い、ボットを作る │
スタート│ 推進中核（養成講座） … 業務テーマを実装し、成果を出す   │
       └──────────────────────────────────┘
                    ↓ 並行して走らせるから、すぐ循環が回る
        推進人材の成果物（業務棚卸し表・実装成果・効果測定・横展開パッケージ）
                    ↓ 365へ戻す
        全社員の学習資産になり、次の推進候補もデータで見つかる
```

**なぜ同時でなければならないか**
- **365だけ**＝学ぶが業務が変わらない（成果が出ない）
- **養成講座だけ**＝一部の人が成果を出しても、受け取る土壌がなく横に広がらない
- **順番にやる**＝基盤づくりの数か月、成果がゼロのまま投資だけが先行する。
  同時に立ち上げれば、推進人材が出した成果を**その時点で**全社が受け取れる

「まず少数から」「基盤を作ってから育成」という表現は**すべて誤り**。

## 2. なぜ2層なのか（提案の論拠）

### 定着ギャップ
- 生成AIを**導入済み 95.6%** ↔ **ほとんどの社員が利用 18.5%**
- アカウントを配るだけでは定着しない。学び続け、試し、共有する運用基盤が必要

### 成果創出の壁
- **AI活用を推進している 87%** ↔ **十分な成果を創出 9%**
- 成果を生む企業の**4条件**＝ ①継続学習 ②推進人材 ③実装機会 ④効果測定
- 学習環境と推進人材を**同時に**設計しないと成果に届かない

### 自社だけでは回し切れない
- **DX推進人材が不足 85.1%** ／ **約2/3がAIを全社展開できていない**
- 教材更新・WS運営・推進人材育成・利用促進と測定が、通常業務との兼務で属人化・停滞する
- 運営はデジライズが担い、貴社は**経営テーマの提示・対象者の選定・現場調整**に集中する

### 役割分担（丸投げではない）
| デジライズ | 貴社 |
|---|---|
| 学習・運営設計（教材更新・WS設計・定着施策） | 経営テーマの提示（優先課題・成果基準・意思決定） |
| 実装伴走（業務棚卸し・検証・効果測定・成果共有） | 対象者の選定（推進候補者・現場協力者・管理職） |
| データ可視化（学習・利用・成果・候補者のKPI） | 現場調整（検証時間・データ・関係部門との連携） |

## 3. 人数設計（100名モデル）

100名の会社なら **70名が日常利用層／30名が推進・成果創出層**。

- **全員を専門家にしない。** 役割分担で使いこなす
- **70名を放置するのは言語道断。** 使わない層を残すと、推進人材の成果が横に広がらない
- **365は全社員に配ることが原則。** 学習の入口を全員に用意する
- **重要なのは人数比そのものではなく、成果が全社に還る導線**（2層は段階ではなく役割分担）
- 初年度は推進テーマと推進中核の人数を絞って始める企業が多い。**配る範囲（365）は絞らない**

登場する役割：全社員（日常業務で使う）／推進者（テーマを見つけ実装）／管理職（優先順位と時間を確保）／事務局（利用状況と成果を可視化）

### 推進リーダーの選抜軸

**「AIに詳しい人」ではなく「業務を変えられる人」。**

| 軸 | 内容 |
|---|---|
| 業務理解 | 現場の課題を言語化できる |
| 実行力 | 小さく試して前へ進める |
| 共有力 | 周囲を巻き込み横展開できる |
| 成果志向 | 効果を測り改善する |

選抜の軸：**技術経験 ＜ 業務を変える意志と行動**

心当たりがない場合は、365を全社に入れて学習・利用データから候補者を見つける進め方ができる
（365は**推進候補者を発見する観測基盤**でもある）。

## 4. 到達レベル（公式4段階・フックツールの中心概念）

**これはデジライズの公式定義。勝手に増やさない・言い換えない。**

| Lv | 名称 | 内容 | 主なツール | 到達手段 |
|---|---|---|---|---|
| **1** | 基礎機能マスター | 生成AIの基本機能を理解し、適切に使いこなせる | **Copilot・Gemini** | 法人リスキリング365 |
| **2** | ルーティンワーク効率化 | 反復作業をAIで効率化し、生産性を向上させる | **Copilot・Gemini**（チャットボット作成） | 法人リスキリング365 |
| **3** | 業務ツール連携 | 業務ツールと連携し、情報の活用と共有を加速する | Word・Excel・Google Workspace | AI人材養成講座 |
| **4** | 簡易コーディング・ワークフロー自動化 | コードと自動化で、業務プロセスを最適化する | GAS・Copilot Studio・VBA ＋ Claude Code / Codex | AI人材養成講座 |

- **レベル1〜2 = 法人リスキリング365**（全社員）／**レベル3〜4 = AI人材養成講座**（推進中核）
- **養成講座はレベル4まで対応する。** ここが2つのサービスの違いそのもの
- レベルは**段階でも順番でもなく、同時に立ち上げる役割分担**
- レベルが上がるほど「人が起動する回数」が減る。これがデモで見せる軸
  - Lv1 毎回頼む → Lv2 仕組みを一度作る → Lv3 つないで一続きにする → **Lv4 誰も起動しないのに動く**

## 4.5 扱うツールと、企業が選ぶ2択

**前提として扱うツール**：ChatGPT / Claude / Copilot / Gemini / Claude Code / Codex

**企業が選ぶのは次の2つだけ。** それ以外は選択肢として提示しない。

| 選択 | 選択肢 | 何を選んでいるか |
|---|---|---|
| `office` | **Copilot**（Microsoft 365）or **Gemini**（Google Workspace） | オフィスソフトの中で使うAI。既にお使いのグループウェアに合わせる |
| `agent` | **Claude Code** or **Codex** | 業務プロセスを自動化するときのエージェント設計ツール |

**レベル1〜2はオフィスAI（Copilot / Gemini）に統一して提示する。** できることが大きく変わらないため、
片方に寄せたほうが伝わり、定着もする。ChatGPT・Claude も学習範囲には含まれるが、
**レベル表やデモのツール表記には出さない**（選択肢が増えて論点がぼやけるため）。

テンプレートでは `CONFIG.choices` にこの2つを入れるだけで、デモの画面名・アプリ名・
業務カードのツール表記がすべて自動で切り替わる（`{{officeAI}}` などのトークン置換）。

## 5. 養成講座の6か月と、残る組織資産

| 月 | 段階 | 内容 |
|---|---|---|
| 1 | 棚卸し | 業務を分解し、課題を可視化 |
| 2 | 発見 | AI活用テーマを見つけ、優先領域を特定 |
| 3〜4 | 設計 | 効果を生む手順と指標を設計 |
| 5 | 検証 | 小さく試し、効果を検証・改善 |
| 6 | 報告 | 成果を報告し、次の改善・横展開へ |

講座終了時に会社へ残る**4つの組織資産**：
①業務棚卸し表（AI適用候補と優先順位）②実装成果（プロンプト・手順・検証結果）
③効果測定（削減時間・品質・改善点）④横展開パッケージ（報告書・次回テーマ・共有資料）

**成果物を365へ戻すことで、成功事例が全社員の学習資産になる。**
講座終了時に残るのは学習履歴ではなく「実務で検証した成果」。

## 6. 費用対効果の語り方

### 控えめな水準で語る

大きな変革を前提にすると「うちには無理」で終わる。
提案資料は「1人1日15分だけ早く終わる」という水準で語っており、フックツールも同じ思想で、
**保守シナリオ（定着30%）を初期表示**にしている。相手が「それくらいなら起こりそうだ」と
思える水準に置くことで、初めて数字が武器になる。

### 投資額はフックツールに載せない

- 金額の提示は**提案資料の役割**。ここで出すと提案本番が要らなくなる
- 代わりに**公的支援2制度の存在だけ**を示し、実質負担が圧縮できることを伝える

| 制度 | 対象 |
|---|---|
| デジタル化・AI導入補助金 | 法人リスキリング365（2年契約の利用料が補助対象経費） |
| 人材開発支援助成金 | AI人材養成講座（受講費用。企業規模で助成額が変わる） |

- **同一経費への重複適用は不可。** それぞれ要件を満たす形で申請・審査
- 補助率・上限・申請手数料の条件があるため、**具体的な数字はフックツールに書かない**
- 「2年契約にすることで補助対象になる」という要件の存在は触れてよい

### 経営判断としての語り（提案資料側の武器・参考）

投資しても課税所得が減り、助成金が戻るため手残りはほぼ変わらない。
「これは費用ではなく、手残りをほぼ変えずに実行できる経営判断です」。
**フックツールでは金額を伴うこの話をしない**（前提が多く、税率も企業ごとに違うため）。

### 1日15分ロジック（参考・提案資料側の武器）

提案資料は「1人1日15分 × 人数 × 20営業日 = 月あたりの価値」で語っている。
フックツールの試算（部門別の積み上げ × 定着率）は別の切り口だが、
**時間単価を3,000円に揃えてある**ため、提案資料と並べても矛盾しない。

## 7. 書いてはいけないこと

| 禁止 | 理由 |
|---|---|
| 投資額・月額・助成金額の具体的な数字 | 提案資料の役割を奪う |
| 「AIが判断します」「全自動」 | 判断は人に残す設計であることが信頼の土台 |
| 人員削減の示唆（「◯名分の人件費が不要に」） | 削減時間は振り替え先があるものとして扱う |
| 提案先の社名 | URLを共有しても特定されない状態を保つ |
| 「使う人だけに配ればよい」という設計 | 思想の否定。断層をつくると横展開しない |
| 単発研修としての表現（「研修を実施します」） | 継続する仕組みであることが差別化そのもの |
| 各AIサービスのロゴ模倣・実在しない機能 | デモは再現イメージである旨を必ず明示 |

## 8. 言葉の統一

- 提案先の呼称 … **貴社**（社名は使わない）
- 自社の呼称 … **デジライズ／私たち**（「弊社」は使わない）
- サービス名 … **法人リスキリング365**／**AI人材養成講座**（略称「365」は文中2回目以降のみ）
- 断定を避ける … 「〜します」ではなく「〜できます／〜する想定です」
