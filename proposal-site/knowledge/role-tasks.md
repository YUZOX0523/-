# 職種・職位別 到達レベルと業務変化カタログ

`CONFIG.departments` を埋めるための素材集。**そのままコピペしない。**
提案先HPから読み取った語彙（商材名・工程名・顧客の呼び方）に言い換えてから使う。

前提として `service-philosophy.md` の**到達レベル**を理解していること。

---

## 1. 業務カードの構造

```js
{ roles:["staff","mgr"],   // どの職位にとっての変化か
  level:2,                 // 到達レベル 1|2|3|4（公式4段階）
  needs:"office",          // "office" / "agent" / 省略（汎用AI）。デモと一致させる
  title:"図面ベースの見積作成",
  before:"…",              // 今の手順（人の動作＋数字）
  after:"…",               // 到達後（人が何に時間を使うかで締める）
  hours:3.0,               // 1人あたり週の削減時間（保守的に）
  demo:"l2-bot" }          // 対応する CONFIG.demos の id（level・needs を一致させる）
```

| 項目 | ルール | 悪い例 | 良い例 |
|---|---|---|---|
| `title` | 動詞で終わる具体的な単位業務 | 「営業DX」 | 「図面ベースの見積作成」 |
| `before` | **人の動作**で描く。数字を1つ入れる | 「非効率な状態」 | 「過去ファイルから探し転記する。1件40〜60分」 |
| `after` | AIの出力で終わらせず、**人が何に時間を使うか**で締める | 「AIが自動で作成」 | 「たたき台が出て、担当者は妥当性の判断だけを行う」 |
| `level` | 下表の公式定義に厳密に従う | — | — |
| `hours` | 1人あたり週の削減時間。**保守的に** | 8.0 | 3.0 |
| `demo` | **同じ `level` かつ同じ `needs` のデモ**を指す | — | — |

### レベルの判定基準（公式4段階・迷ったらこれで決める）

| Lv | 名称 | 判定 | 到達手段（自動表示） |
|---|---|---|---|
| **1** | 基礎機能マスター | AIに指示を出して下書き・要約・整理を受け取る。**都度の依頼で完結する** | 法人リスキリング365 |
| **2** | ルーティンワーク効率化 | **業務専用のボットを一度作り、繰り返し使う／同僚に配る。** 反復作業が対象 | 法人リスキリング365 |

レベル1〜2のツール表記は **Copilot / Gemini に統一**する（`needs:"office"`）。
| **3** | 業務ツール連携 | **複数の業務ツールをつないで一続きにする。** 情報の活用と共有が加速する。まだ人が起動する | AI人材養成講座 |
| **4** | 簡易コーディング・ワークフロー自動化 | **人が起動しなくても業務が回る。** トリガー・判定・通知・承認の設計が必要 | AI人材養成講座 |

判定の勘所は「**人が起動する回数**」：
- 「毎回自分で頼む」なら **Lv1**
- 「仕組みを一度作って、あとは使うだけ」なら **Lv2**
- 「1回頼めば複数ツールをまたいで一続きに動く」なら **Lv3**
- 「誰も起動しないのに動いている」なら **Lv4**

### カードの配り方

- 1部門あたり **5枚**。各部門で `exec` / `mgr` / `staff` のどれを選んでも**1枚以上出る**ように `roles` を配る
- **全部門に Lv3 か Lv4 を1枚は置く。** 養成講座の価値が部門ごとに見えないと、推進人材の予算が付かない。
  商談相手の部門には必ず Lv4 を入れる
- **Lv1〜2 を全体の半分以上置く。** ここが365の範囲であり、全社員に関係する話だから
- `needs` は紐づけるデモと必ず一致させる（カードのツール表記とデモの画面が食い違うため）
- `exec` のカードは「判断材料が上がってくる」視点で書く（経営層自身がボットを作る前提にしない）
- 現場作業者（製造・物流・店舗）は作業そのものは減らない。**記録・報告・問い合わせ**に絞り、`hours` は 0.8〜1.2

### 禁止事項

- 「AIが判断します」と書かない
- 人員削減を示唆する表現を使わない
- 断定形（「〜になります」）ではなく想定形（「〜できます」）で書く
- 提案先に存在しない部門を入れない（工場を持たない会社に「製造現場」を出さない）

## 2. 週あたり削減時間の目安（1人あたり・保守見積）

| 対象 | 目安 |
|---|---|
| 経営層 | 1.0〜2.5h |
| 管理職 | 1.5〜4.0h |
| 営業・事務・企画 | 2.0〜3.5h |
| 専門職（士業・医療・設計） | 2.0〜4.0h |
| 現場作業（製造・物流・店舗） | 0.8〜1.2h |
| 技術・情報システム | 3.0〜4.5h |

部門ごとの人数は `CONFIG.roi.rows[].heads` に置く（試算の内訳表に出る）。
合計が「対象人数」として画面に表示されるため、プロフィールの「対象◯◯名」と一致させ、
公表従業員数を超えないようにする。

## 3. 共通部門カタログ（業種を問わず出てくる）

各項目に `Lv` を付記。カッコ内は推奨ツール。

### 経営・企画
- `Lv1` 月次経営会議の資料づくり — 各部門のExcelを手作業で統合 → 統合・前月比コメントまで下書き（copilot）
- `Lv2` 経営判断のための情報収集 — 都度検索で整理できていない → 論点と出典条件を仕込んだ調査ボットで毎回同じ品質（gemini）
- `Lv2` 稟議・社内通達の作成 — 過去文書を探して体裁を真似る → 自社書式を覚えた文書ボットに要点を渡す（gemini）
- `Lv3` 部門横断の数字集めそのもの — メールで依頼して待つ → 締め日に自動集約し差分だけ人に確認（claudecode）

### 営業
- `Lv2` 見積・提案書の作成 — 過去案件を探して転記 → 実績と単価表を覚えた見積アシスタントを自分で作る（gemini）
- `Lv2` 問い合わせの一次回答 — 都度過去メールを検索 → 自社の言い回しを覚えたボットが下書き（copilot）
- `Lv1` 訪問記録と共有 — 個人ノートで止まる → 議事録・次アクション・共有文まで整う（gemini）
- `Lv3` 引き合いから見積提出までの流れ — 取りこぼしが起きる → 受信検知・案件登録・下書きまで進めて承認待ち（codex）

### カスタマーサポート・受付
- `Lv2` よくある問い合わせの一次回答 — 同じ回答を何度も書く → FAQを覚えたボットに任せ、人は確認（copilot）
- `Lv2` FAQ・マニュアルの整備 — 更新が追いつかない → 実際の問い合わせから更新差分を出すボット（gemini）
- `Lv3` 問い合わせの振り分けと記録 — 目視で分類 → 分類・一次回答・記録まで回し、例外を人へ（copilot）

### 管理部門（経理・人事・総務）
- `Lv2` 社内規程の問い合わせ対応 — 担当者が規程を読み直して個別回答 → 規程QAボットで社員が自己解決（copilot）
- `Lv1` 採用・評価の文書作成 — 毎回ゼロから書く → 要件から粒度の揃った草案（gemini）
- `Lv3` 請求・支払データの突合 — 目視照合で残業 → 差分抽出を自動化し例外だけ人へ（claudecode）
- `Lv3` 経費・稟議のチェック — 全件目視 → ルール違反候補を抽出し、判定は人（claudecode）

### マーケティング
- `Lv2` コンテンツ制作 — 担当者1人に依存 → トーンと構成を覚えたボットで初稿、人は事実確認（gemini）
- `Lv3` 顧客データの分析と定例レポート — 分析できる人がいない → 集計・可視化・レポートまで自動（claudecode）

### 技術・情報システム
- `Lv2` 社内からの問い合わせ対応 — 同じ回答を個人宛に何度も → マニュアルを覚えたヘルプデスクボット（copilot）
- `Lv3` 古い社内資産の解読と作り直し — 中身を知る人がいない → 仕様化して置き換えまで進める（claudecode）
- `Lv3` 現場向けツールの開発 — 着手まで数ヶ月 → その日のうちに動く試作（codex）
- `Lv3` システム間のデータ連携 — 手作業CSV運用、担当者が休むと止まる → 自動化しエラー時だけ人が見る（codex）

## 4. 業種別の固有業務

HPから業種を判定し、共通カタログに**その業種固有のものを2〜3件混ぜる**。
固有業務が入っているかが「うちのことを分かっている」と感じてもらえる分かれ目。

### 製造業
- `Lv2` 図面ベースの個別見積（gemini）／`Lv2` 段取り相談ボット（copilot）
- `Lv2` 検査データの傾向確認（copilot）／`Lv3` 品質データの日次監視と月次報告（claudecode）
- `Lv1` 是正処置報告書の下書き（copilot）／`Lv3` 日報の集約と異常検知（gemini・claudecode）
- `Lv1` 技能ノウハウの言語化（gemini）

### 建設・不動産
- `Lv2` 積算・拾い出しの下ごしらえ（gemini）／`Lv2` 入居者・施主の問い合わせボット（copilot）
- `Lv1` 施工写真・日報の報告書化（copilot）／`Lv3` 安全パトロール記録の集計と通知（claudecode）
- `Lv2` 物件情報の掲載原稿ボット（gemini）

### 卸売・小売
- `Lv2` 商品説明・POP原稿ボット（gemini）／`Lv2` 店舗別売上の要因確認（copilot）
- `Lv3` 発注・在庫データの異常検知（claudecode）／`Lv3` 受発注データの取り込み（codex）

### 運輸・物流
- `Lv1` 配車・積載計画の案出し（copilot）／`Lv2` 荷主問い合わせの一次回答ボット（copilot）
- `Lv3` 点検・運行記録の集約と期限管理（codex）／`Lv1` 遅延・事故報告書の下書き（copilot）

### IT・通信・SaaS
- `Lv2` 仕様書・設計書の下書きボット（claudecode）／`Lv2` リリースノート・ヘルプ記事ボット（gemini）
- `Lv3` 既存コードの調査と影響範囲の特定（claudecode）／`Lv3` 障害の一次切り分けと通知（claudecode）
- `Lv3` 機能開発そのものの速度（codex）

### 医療・福祉
- `Lv1` 記録・申し送りの下書き（copilot）※個人情報の取り扱いは必ずQ&Aで触れる
- `Lv2` 加算・書類要件のチェックボット（copilot）／`Lv2` 家族向け説明文書ボット（gemini）
- `Lv1` シフト・人員配置の案出し（copilot）

### 専門サービス（士業・コンサル）
- `Lv2` 調査・リサーチの一次まとめボット（gemini）／`Lv2` 報告書の構成と初稿ボット（gemini）
- `Lv3` 契約書・規程のレビュー観点の自動抽出（claudecode）／`Lv1` 面談記録からの論点整理（gemini）

### 金融・保険
- `Lv1` 稟議・審査資料の下書き（copilot）／`Lv2` 顧客向け説明資料ボット（gemini）
- `Lv2` 規制・ガイドライン改定の影響整理ボット（gemini）／`Lv3` データの突合・異常検知（claudecode）

### 教育
- `Lv2` 教材・課題の作成と難易度調整ボット（gemini）／`Lv2` 保護者向け通知文ボット（gemini）
- `Lv1` 成績・出欠データの傾向把握（copilot）／`Lv3` 出欠・提出物の集約と督促（codex）

### 飲食・宿泊
- `Lv2` 予約・問い合わせの一次対応ボット（copilot）／`Lv2` メニュー・館内案内の多言語化ボット（gemini）
- `Lv1` 売上・客数の要因分析（copilot）／`Lv1` シフト作成（copilot）
